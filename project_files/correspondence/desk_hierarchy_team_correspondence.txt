The hierarchy in Manifest is Desk Location Type → Desk Location, and the desk locations you listed are assigned under the applicable type. For example, if the team is Documentation and Demand Packages, there would be a desk location type of the same name, and within that type, we may include several desk locations such as Pending, Transactional, Closed, etc.  

The ability to create Desk Location Types and Desk Locations is role-based. The system is designed so that the role granting the capability to create Desk Location Types and Desk Locations can be assigned to any user; however, it is typically assigned to the BA or IT, and we would like to maintain that flexibility.

User assignment:
Managers or anyone with the appropriate role can associate a user with any desk location from which their work will be delivered. This is not a 1:1 relationship. A single user can be associated with multiple desk locations across various desk location types, and this association can be fluid and change on a day-to-day basis, depending on workflow needs. 

We assign desks to users in priority order (currently up to five). This ensures the user always receives work without having to search for it. If work runs out on the first-priority desk, the system automatically shifts the user to their next assigned desk in sequence. Likewise, if new work becomes available in a higher-priority desk, that work becomes the next task the user receives. Standard desk locations:
The list shown in the process document reflects the desk locations we commonly use within each type, but it is not currently a required or system-standard set. We value the flexibility to add Desk Location Types and Desk Locations as needed. That said, if the system presented a default set of desk locations whenever a new Desk Location Type is created, with the option for the user to activate, deactivate, or leave any of them dormant, this could save time and ensure that the user setting up the desks is considering all of the desk location types we typically use to manage work. Maintaining the ability to adjust these manually would still give us the control we need.

Apologies for the confusion. To clarify our current structure:

•  A desk type represents the phase of the process the work is in. 

Examples:  Evaluation, Adverse Coverage Verification, Pursuit of Recovery.  
It is the team grouping, but it does not contain users directly.  

• A desk location does not represent the team.

It represents the pool of work from which the workflow delivers inventory to the user.
Users are then assigned to a desk location so they can receive work from the workflow. 

• Desk Type is used to define information based on the stage of the process (email address, phone number, fax number) that prints on letters generated by the system.

Here is an example based on how the workflow currently functions:

Claim ABC123 first enters workflow and is assigned to the Desk Type: Evaluation and routed to the Desk Location: Evaluation – Transactional.

User Jon Doe, who is assigned to that desk location, receives Claim ABC123 to work.

Once Jon completes his portion, workflow moves the claim to the next phase: Desk Type: Adverse Coverage Verification and Desk Location: Adverse Coverage Verification – Transactional.

User Jane Doe, who is assigned to Desk Location: Adverse Coverage Verification – Transactional, receives the claim for her step in the process. 

During her review, Jane determines that she cannot verify coverage without additional information. She generates a letter to the appropriate party requesting the information. The letter includes the contact information associated with that workstage so that any response is directed back to the Adverse Coverage Verification workstage. Jane then reassigns the claim to Desk Type: Adverse Coverage Verification and Desk Location: Adverse Coverage Verification – Request for Information, where it remains until the necessary information is obtained.  


Because Desk Type is used primarily to supply contact details for letters, we may be able to simplify the structure. One option to explore would be to eliminate the Desk Type and use desk location naming to indicate both the team and the type of work housed on that location (for example: Pending, Transactions, Request for Information, etc.).

We can adjust the approach based on your recommendations as you continue shaping the design.
